Como a regra funciona por trás da interface e da API.

Um resumo técnico da lógica de escalas, da API FastAPI, da persistência em JSON/PostgreSQL e da arquitetura em camadas usada no projeto.

Ciclo por dias

Usa a soma dos dias trabalhados e dos dias de folga para formar um ciclo. A posição da data consultada dentro desse ciclo define se o status será trabalho ou folga. 

ciclo = dias_trabalho + dias_folga
dias_passados = data_consulta - data_inicio
posicao = dias_passados % ciclo

status = "Trabalhando" se posicao < dias_trabalho
status = "Folga" caso contrário

Exemplos atendidos por esse tipo: 6x3, 5x2 e 4x2.

Ciclo por horas

Segue o mesmo princípio do ciclo por dias, mas calcula a posição usando data e hora. É útil para escalas como 12x36. 

ciclo = horas_trabalho + horas_folga
horas_passadas = data_hora_consulta - data_hora_inicio
posicao = horas_passadas % ciclo

status = "Trabalhando" se posicao < horas_trabalho
status = "Folga" caso contrário

Na API, esse modelo exige hora_inicio e hora_consulta para calcular corretamente o status.

Turno rotativo

Usa uma sequência personalizada. Cada posição da lista representa um dia do ciclo. O sistema calcula em qual posição a data consultada cai. 

sequencia = ["Manhã", "Tarde", "Noite", "Folga"]
dias_passados = data_consulta - data_inicio
posicao = dias_passados % len(sequencia)

status = sequencia[posicao]

Comparação de duas escalas

A tela Comparador calcula os dois lados pelo mesmo núcleo de calendário usado pelo simulador. Cada escala tem âncora e parâmetros independentes; a data selecionada e o horário observado são comuns.

É possível ajustar uma configuração sem salvá-la. O resumo do mês conta apenas os status no horário selecionado, não dias completos nem horas trabalhadas. Em ciclos por horas, os detalhes da data mostram também os intervalos reais entre trabalho e folga.

No GitHub Pages, escalas salvas vêm do armazenamento do navegador e a página não consulta a API local. No servidor estático local, pode listar escalas do navegador ou da API local disponível. A API é demonstrativa, sem autenticação ou separação por usuário.

Relatório mensal

A tela Relatório mostra um calendário mensal de uma escala ou compara duas, com inícios de ciclo independentes. O mês exibido só muda para o mês do início quando o botão correspondente é acionado. Modelos e escalas salvas podem receber ajustes temporários que não alteram os dados originais.

Calendário, tabela detalhada, impressão, XLSX e CSV vêm do mesmo resultado calculado pelo núcleo compartilhado. Para ciclos por dias não há horário obrigatório. Se uma escala usa horas, o horário selecionado é o instante observado em cada data; os totais não representam dias inteiros nem horas trabalhadas. Em 12x36 pode haver troca de trabalho e folga dentro da mesma data.

O XLSX traz calendário, legenda, resumo e aba de registros; seu gerador local report-xlsx.js não usa dependência externa nem CDN. A impressão usa o navegador. O CSV sem formatação traz metadados e os registros da prévia em UTF-8 com BOM e separador ;; se o Excel abrir tudo em uma coluna, importe usando esse separador. Textos que poderiam virar fórmulas são protegidos. No GitHub Pages, a página usa somente escalas deste navegador e não consulta a API local. A API de demonstração não tem autenticação nem isolamento por usuário e deve continuar restrita ao uso local.

API FastAPI

A API expõe parte das funcionalidades do simulador por HTTP. A demo pode usar essa API local para modelos e escalas salvas; sem backend, o cálculo e os cadastros funcionam no navegador. 

GET    /health
GET    /api/v1/modelos
GET    /api/v1/escalas
POST   /api/v1/escalas
DELETE /api/v1/escalas/{nome}

POST   /api/v1/simulacao/status
POST   /api/v1/simulacao/proximos-dias

Para testar a integração local, execute:

uvicorn api.app:app --reload

Persistência

A API usa JSON em data/escalas.json por padrão. PostgreSQL existe como alternativa para a aplicação CLI e não é necessário para executar a API ou a demo pública.

ESCALA_REPOSITORY=json      # CLI: padrão
ESCALA_REPOSITORY=postgres  # CLI: PostgreSQL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=SUA_SENHA_AQUI
POSTGRES_DB=simulador_escala
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5432

Instalação, uso offline e proteção dos dados

Depois de uma visita online completa, as páginas do simulador, comparador e relatório ficam disponíveis sem conexão. No Android, use a opção de instalação oferecida pelo Chrome ou seu menu. No iPhone, abra no Safari e escolha Compartilhar → Adicionar à Tela de Início.

As escalas salvas neste navegador ficam neste dispositivo, sem sincronização. A consulta guardada no simulador lembra o modelo, os parâmetros e o início que você confirmou, mas é separada dos cadastros. Abra Dados locais para baixar um backup JSON v1 ou restaurá-lo após conferir a prévia e confirmar a substituição. Esse backup guarda apenas os cadastros de escalas; após importar, confirme novamente o início da consulta e também no protótipo Android. A restauração não inclui escalas da API local. Limpar os dados do navegador ou desinstalar pode apagar as escalas locais.

O aplicativo aguarda o fechamento das páginas antigas antes de ativar uma atualização offline, preservando o armazenamento local. No GitHub Pages não há chamadas para a API em localhost; em um servidor estático local, a API continua opcional.
