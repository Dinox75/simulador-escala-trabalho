Como a regra funciona por trás da interface e da API.

Um resumo técnico da lógica de escalas, da API FastAPI, da persistência em JSON/PostgreSQL e da arquitetura em camadas usada no projeto.

Ciclo por dias

Usa a soma dos dias trabalhados e dos dias de folga para formar um ciclo. A posição da data consultada dentro desse ciclo define se o status será trabalho ou folga. 

ciclo = dias_trabalho + dias_folga
dias_passados = data_consulta - data_inicio
posicao = dias_passados % ciclo

status = "Trabalhando" se posicao < dias_trabalho
status = "Folga" caso contrário

Exemplos atendidos por esse tipo: 6x3, 5x2 e 4x2.

Ciclo por horas

Segue o mesmo princípio do ciclo por dias, mas calcula a posição usando data e hora. É útil para escalas como 12x36. 

ciclo = horas_trabalho + horas_folga
horas_passadas = data_hora_consulta - data_hora_inicio
posicao = horas_passadas % ciclo

status = "Trabalhando" se posicao < horas_trabalho
status = "Folga" caso contrário

Na API, esse modelo exige hora_inicio e hora_consulta para calcular corretamente o status.

Turno rotativo

Usa uma sequência personalizada. Cada posição da lista representa um dia do ciclo. O sistema calcula em qual posição a data consultada cai. 

sequencia = ["Manhã", "Tarde", "Noite", "Folga"]
dias_passados = data_consulta - data_inicio
posicao = dias_passados % len(sequencia)

status = sequencia[posicao]

API FastAPI

A API expõe parte das funcionalidades do simulador por HTTP. A demo pode usar essa API local para modelos e escalas salvas; sem backend, o cálculo e os cadastros funcionam no navegador. 

GET    /health
GET    /api/v1/modelos
GET    /api/v1/escalas
POST   /api/v1/escalas
DELETE /api/v1/escalas/{nome}

POST   /api/v1/simulacao/status
POST   /api/v1/simulacao/proximos-dias

Para testar a integração local, execute:

uvicorn api.app:app --reload

Persistência

A API usa JSON em data/escalas.json por padrão. PostgreSQL existe como alternativa para a aplicação CLI e não é necessário para executar a API ou a demo pública.

ESCALA_REPOSITORY=json      # CLI: padrão
ESCALA_REPOSITORY=postgres  # CLI: PostgreSQL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=SUA_SENHA_AQUI
POSTGRES_DB=simulador_escala
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5432

Arquitetura em camadas

O projeto separa interface, validação, regra de negócio, API e persistência. Isso facilita manutenção, testes e evolução para versões futuras. 

CLI / Demo web
  ↓
API FastAPI
  ↓
Routes
  ↓
EscalaService
  ↓
EscalaRepository
  ├── JsonEscalaRepository
  └── PostgresEscalaRepository
      ↓
      JSON ou PostgreSQL
